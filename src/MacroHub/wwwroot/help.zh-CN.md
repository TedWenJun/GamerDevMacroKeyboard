# MacroHub 帮助

MacroHub 是宏键盘的**系统层**：把宏键盘上的每个物理控件变成可配置的"功能"，按前台应用自动切换，并可把功能事件交给应用（如 UE 插件）原生处理。本页随功能更新，最新变化见文末 [更新记录](#changelog)。

> 配置界面：<http://127.0.0.1:17900/> · 本页：<http://127.0.0.1:17900/help.html> · 源文件：`src/MacroHub/wwwroot/help.zh-CN.md`（English: `help.en.md`）

---

## 快速开始 {#quick-start}

1. 启动：安装版从开始菜单打开 **MacroHub**（或运行 `MacroHub.exe --open`）；从源码运行用 `.\scripts\run.ps1`。需要向管理员权限窗口发快捷键时，以管理员身份运行（源码：`run.ps1 -Elevated`；安装版：`install.ps1 -AutoStartElevated`）。浏览器会自动打开配置界面。
2. 看顶部状态：**宏键盘在线**、**键盘钩子** 都是绿色即可使用。
3. 点层标签切到要编辑的层 → 点按键 → 在右侧选择功能。
4. 点右上角 **保存并应用**，立即生效（无需重启）。
5. 点 **设为激活层**，让宏键盘开始使用该层。

界面语言默认跟随浏览器，顶部 **EN / 中文** 按钮可切换。

## 核心概念 {#concepts}

| 概念 | 说明 | 例子 |
|---|---|---|
| **控件** | 宏键盘上的一个物理输入 | `K1`（按键 1）、`KNOB_CW`（旋钮右旋）、`JOY_PRESS`（摇杆按下） |
| **功能** | 与硬件、应用都无关的语义命令，带一个默认动作 | `ue.play`（PIE 运行，默认 `Alt+P`） |
| **层** | 一套"控件 → 功能"的映射，同一时间只有一个层生效 | 原厂数字键盘、通用办公、UE 编辑器 |
| **应用档案** | 按前台程序匹配，可自动切层、覆盖功能的动作、转发给应用 | `UnrealEditor.exe` 前台时切到"UE 编辑器"层 |

一次按键的处理顺序：**物理控件 → 当前层找到功能 → 应用档案覆盖（若有）→ 执行动作 / 转发给应用**。

"当前层"的决定方式：前台应用的档案指定了层时用它；否则用**手动激活层**（"设为激活层"按钮或"下一层/上一层"功能设置）。

## 界面导览 {#tour}

### 顶部状态栏 {#status-bar}

| 状态 | 含义 |
|---|---|
| 已连接 Hub | 页面与 MacroHub 的实时连接 |
| 宏键盘在线 · USB / 2.4G / 蓝牙 | 已打开宏键盘的厂商数据通道（识别物理按键所必需），后面是当前连接方式 |
| 电量 / 充电中 | 宏键盘电池，每 30 秒读取一次；20% 以下变黄、10% 以下变红。有线连接时显示“充电中” |
| 键盘钩子 | 已安装系统键盘钩子（拦截原始按键所必需） |
| 拦截 | 当前拦截模式，见 [设备与拦截](#device) |
| 前台 | 当前前台进程，以及匹配到的应用档案 |
| 当前层 | 正在生效的层 |
| 应用客户端 | 通过命名管道或 WebSocket 接入 MacroHub 的应用数量（如阶段二的 UE 插件）。接入的应用在前台、且其档案开启转发时，由应用处理，不再模拟快捷键；未接入时为 0，功能照常以快捷键执行。悬停查看已连接应用的通道、协议版本、运行模式和回报的上下文，点击跳到测试台列表。详见 [应用客户端协议](#app-protocol) |
| 非管理员 | MacroHub 未以管理员身份运行时显示；此时无法向管理员权限窗口发送快捷键 |

右上角 **保存并应用 / 撤销修改**：界面上的所有修改先存在页面里，保存后才写入配置并生效。

### 托盘图标 {#tray}

MacroHub 没有自己的窗口，运行时在任务栏通知区域显示一个图标：

- **黄色菱形**外围是一个底部开口的**圆环**，就是电量条：从左下角顺时针填充，绿色；20% 以下变黄，10% 以下变红。只剩灰色底环表示键盘未连接（或刚连上、尚未读到电量）。
- 悬停显示版本、连接方式、电量与当前层；**左键**打开配置页；**右键**菜单显示与顶部状态栏相同的信息，并可打开帮助、日志文件夹或退出 MacroHub。
- 使用 `--no-tray` 启动时不显示托盘图标。

### 层标签栏 {#layer-tabs}

- 点标签切换**正在查看/编辑**的层（不会改变正在生效的层）。
- 带"激活"标记的是当前生效层。
- **设为激活层**：把正在查看的层设为手动激活层。
- **层属性**、**+ 新建层**、**删除层**：见 [层](#layers)。

### 按键视图 {#key-view}

- 每个按键显示按键标签和本层绑定的功能名。
- `↳功能名`（灰色）表示本层没绑定、继承自基础层。
- `未绑定·原样输出` / `未绑定·屏蔽` 表示本层未绑定时的处理方式。
- 旋钮分为 左旋 / 右旋 / 按下 三个区域；摇杆分为 上 / 下 / 左 / 右 / 按下 五个区域，分别点击编辑。
- 实体按键按下时对应位置会闪白；被拦截的按键边框闪红。

### 右侧检查器 {#inspector}

选中控件后显示：

- **硬件签名**：识别该控件的信号，见 [学习按键](#learn)。
- **本层绑定的功能**：下拉选择，或"+ 新建功能…"。
- **模拟按下**：按已保存的配置走一遍完整流程（会真的执行动作，发往当前焦点窗口）。
- **功能**：修改名称、分类和默认动作。注意功能被多个层共用时，改默认动作会影响所有使用它的地方（右上角显示"被 N 处使用"）。
- **应用覆盖**：勾选某个应用，为它单独设置该功能的动作。
- **旋转灵敏度 / 按键触发**：见 [输入设置](#input-settings)。

## 层 {#layers}

### 新建层 {#new-layer}

点 **+ 新建层**，填写：

- **层名称**、**颜色**（颜色用于标签和激活标记）。
- **初始绑定**：空白（未绑定的按键按"继承基础层"处理），或复制某个已有层的全部绑定作为起点。

### 层属性 {#layer-properties}

| 设置 | 说明 |
|---|---|
| 层名称 / 颜色 | 显示用 |
| 本层未绑定的按键 | **继承基础层**：沿用第一个层的绑定；**原样输出**：宏键盘原本的按键照常输入；**屏蔽**：什么都不发生（适合游戏、演示时防误触）。基础层选"按全局设置"时，使用 [设备与拦截](#device) 里的"未绑定按键"设置 |
| 这些应用在前台时自动切到本层 | 勾选应用档案。一个应用只能自动切到一个层，勾选会覆盖它原来的设置 |
| 左移 / 右移 | 调整顺序；"下一层 / 上一层"功能按此顺序循环 |
| 设为基础层 | 移到第一位。基础层是其他层"继承"时的来源 |
| 复制此层 | 在右侧插入一份副本 |
| 内部 id | 被应用档案和"切换层"动作引用，不可修改 |

### 删除层 {#delete-layer}

切到要删的层，点 **删除层**。确认框会列出影响：是否为基础层、是否为当前激活层、哪些应用将不再自动切层、哪些"切换到该层"的动作会失效。删除后点保存才生效，保存前可撤销。至少保留一个层。

### 默认层 {#default-layers}

| 层 | 用途 |
|---|---|
| 原厂数字键盘 | 基础层，全部原样输出，等同于不使用 MacroHub |
| 通用办公 | 复制、粘贴、撤销、截图、显示桌面、媒体控制等 |
| UE 编辑器 | PIE、Simulate、Live Coding、移动/旋转/缩放工具、视图模式；`UnrealEditor.exe` 前台时自动启用 |
| 游戏 | 按住同步的 1–4、空格、WASD；`*-Win64-Shipping.exe` 等打包游戏前台时自动启用 |
| 拦截测试·全屏蔽 | 所有控件都屏蔽，用于验证拦截效果 |

## 输入设置 {#input-settings}

控件产生的物理动作不一定一次对应一次快捷键。在右侧检查器底部为每个控件设置：

**旋钮左旋 / 右旋（旋转灵敏度）**

| 设置 | 说明 | 默认 |
|---|---|---|
| 每转几格触发一次 | 转满 N 格才执行一次动作，例如切换浏览器标签设为 3 | 1 |
| 最小触发间隔 | 两次触发之间至少间隔多少毫秒，转得再快也不会更频繁；0 为不限制 | 0 |
| 停顿多久清零 | 未转满的格数在停顿这么久后清零 | 800 ms |
| 左旋 / 右旋使用相同设置 | 修改时同时写入另一方向 | 勾选 |

反向旋转会重新计数。

**按键、摇杆方向、旋钮按下（按键触发）**

| 设置 | 说明 | 默认 |
|---|---|---|
| 按住连发 | 按住不放时重复执行动作（W909 摇杆是四向开关，按住连发即“持续推动”） | 关 |
| 首次重复前延迟 / 重复间隔 | 与系统键盘连发类似 | 400 / 100 ms |
| 最小触发间隔 | 防止快速连按重复触发 | 0 |

按住连发不适用于“按住同步”类快捷键（它们本身就跟随按下和松开）。

**作用范围与优先级**：

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1（最高） | 某层单独设置 | 存在该层里，每层可不同 |
| 2 | 共用设置 | 存在控件本身，**全局只有一份**：在任何层里改共用设置，改的都是同一个值（后改覆盖先改），影响所有没有单独设置的层 |
| 3 | 默认值 | 每格触发、不连发 |

检查器里会列出共用设置的值、哪些层在使用它、哪些层有单独设置（点层名可跳转）。切换“共用设置 / 本层单独设置”不会改动任何数值：改回共用就是删除本层的单独设置；改为单独设置时以当前共用值为起点。

**注意**：

- 输入设置只影响本地快捷键和功能事件转发。以“转发原始控件”方式发给应用（如 UE 插件）时，每一格、每一次都会发送，灵敏度由应用自己决定（例如时间轴需要逐帧精度）。
- 没有触发的格子依然会拦截原始按键并执行 [旋钮音量保护](#volume-guard)。
- “实时事件”里控件事件会显示进度（如 `格数=2/3`）和“未触发”；连发显示为 `repeat`。

## 功能与动作 {#functions}

在 **功能库** 页查看全部功能、直接执行测试、新建或删除（仍被层使用的功能不能删除）。

- **搜索**：匹配名称、ID、分类、快捷键/动作内容、使用位置（层名、按键名）和应用覆盖；多个词用空格分隔需同时匹配，命中文字高亮。功能库页面按 `/` 聚焦搜索框，`Esc` 清空。
- **筛选**：按分类，或按使用情况（已绑定到按键 / 未使用 / 有应用覆盖）。右侧显示匹配数量。
- **使用位置**：列出每个绑定该功能的“层·按键”，点击跳到对应层并选中按键。

| 动作类型 | 说明 | 示例 |
|---|---|---|
| 快捷键 | 组合键，逗号分隔表示依次按下；可点"录制"直接按键录入 | `Ctrl+Shift+S`、`Ctrl+K, Ctrl+C` |
| 快捷键 · 按住同步 | 控件按下时按下、松开时松开（只取第一个组合键），游戏移动/持续动作用 | `W` |
| 输入文本 | 直接输入任意 Unicode 文本，换行会发送回车 | `Hello 中文` |
| 宏序列 | 若干步：按键 / 文本 / 延时（毫秒，单步最长 10 秒） | `Ctrl+A` → 延时 50 → `Ctrl+C` |
| 运行程序 | 程序、文件或网址，支持环境变量 | `calc.exe`、`%USERPROFILE%\Desktop` |
| 鼠标 | 按键（左/右/中/X1/X2，可按住）或滚轮格数 | 滚轮 `+1` |
| 切换层 | 下一层 / 上一层 / 指定层 | 旋钮按下 → 下一层 |
| 仅转发给应用 | 只把功能事件发给已连接的应用客户端，本地不执行 | UE 插件原生处理 |
| 原样输出 | 宏键盘原本的按键照常输入 | — |
| 屏蔽 | 什么都不做 | — |

可用键名：字母、数字、`F1`–`F24`、`Ctrl` `Shift` `Alt` `Win`、`Enter` `Esc` `Tab` `Space` `Backspace` `Delete`、方向键 `Up` `Down` `Left` `Right`、`Home` `End` `PageUp` `PageDown`、小键盘 `Num0`–`Num9` `NumAdd` 等、媒体键 `VolumeUp` `VolumeDown` `VolumeMute` `MediaPlayPause`、符号 `-` `=` `[` `]` `;` `'` `,` `.` `/` `` ` ``。输入框有自动补全。

> UE5 在 Windows 上不识别 `F13`–`F24`，给 UE 用的快捷键请避开它们。

## 应用档案 {#apps}

在 **应用档案** 页管理：

- **进程**：可执行文件名，逗号分隔，支持 `*` 通配，如 `*-Win64-Shipping.exe`。
- **前台时自动切换到层**：也可以在层属性里勾选。
- **转发给应用客户端**：该应用接入 MacroHub（见 [应用客户端协议](#app-protocol)）后收到什么：

| 模式 | 应用在线时 | 应用离线时 |
|---|---|---|
| 不转发 | 按本地动作执行 | 同左 |
| 转发功能事件 | 收到 Hub 层映射后的功能（如 `ue.play`），由应用处理，本地不执行 | 本地动作 |
| **转发原始控件** | 跳过 Hub 的层，收到原始控件（如 `KNOB_CW`），由应用按自身上下文决定功能 | Hub 的层 + 本地动作 |

  默认的 Unreal Editor / UE 打包游戏档案使用 **转发原始控件**：同一个旋钮在 Sequencer、动画编辑器里拖动时间，在动画蓝图里切换子标签页，这类“按编辑器焦点区分功能”的逻辑由 UE 插件实现，Hub 无法看到 UE 内部焦点。
- **覆盖**：在按键检查器的"应用覆盖"里为具体功能设置。

## 学习按键 {#learn}

每个控件的**硬件签名**决定 MacroHub 如何认出它：

| 签名 | 含义 |
|---|---|
| `vendor:48` | 厂商位图第 48 位，物理按键的唯一身份（不随固件模式变化） |
| `key:61` | 出厂固件发出的键码（十六进制虚拟键，这里是小键盘 1） |
| `consumer:0E9` | Consumer 用途码（这里是音量+） |

更换设备、切换 NumLock 或发现某个控件没反应时：选中控件 → 点 **学习** → 在宏键盘上按一下（旋钮/摇杆做对应动作）。学习到的签名立即保存并生效。

## 测试台 {#test-bench}

- **实体按键拦截测试**：切到会拦截的层（如"拦截测试·全屏蔽"）并设为激活层，点输入框后按宏键盘。拦截成功时输入框里不会出现字符。
- **统计**：物理按下 / Hub 拦截 / **泄漏**（原始按键漏过去的次数）/ 等待次数与最长等待。泄漏持续增加时，可调大下方"钩子等待物理报告的时间"（默认 8 ms）。统计点"重置"清零。
- **动作测试**：不经过按键，直接执行一个动作。
- **应用客户端**：列出已注册的应用。

## 设备与拦截 {#device}

### 拦截模式 {#interception}

| 模式 | 适用 | 原理 |
|---|---|---|
| **关联**（默认） | 出厂固件，有线或 2.4G 接收器 | 直接读取宏键盘厂商通道的物理按键报告（比系统键盘钩子早约 1–2 ms），按下后短时间内到达的硬件按键判定为宏键盘发出并拦截。主键盘不受影响，与固件模式无关 |
| **按键码** | 固件改成独有键码（如 F13–F24），或没有厂商通道的连接方式（如蓝牙，待验证） | 凡是出现在控件 `key:` 签名里的键码一律视为宏键盘 |
| **关闭** | 调试 | 从不拦截，只执行动作 |

### 未绑定按键 {#unbound}

基础层在"按全局设置"时，未绑定控件是 **原样输出** 还是 **屏蔽**。

### 旋钮音量保护 {#volume-guard}

W909 旋钮在硬件层固定发送“音量±”，Windows 会直接调节系统音量，键盘钩子拦不住（固件切换模式后也一样）。开启 **旋钮音量保护**（默认开启）后，当旋钮被绑定到非音量功能、被屏蔽、或作为原始控件转发给应用时，MacroHub 会在 Windows 改完音量后立即恢复原值。屏幕上的音量提示可能会闪一下。

旋钮绑定的就是“音量+ / 音量−”快捷键时，MacroHub 不会再额外发送一次（避免一格调两次），也不会触发保护。设置页会显示音频设备状态和已恢复次数。

### 设备匹配 {#device-match}

"匹配"填 HID 设备路径包含的子串（如 `VID_B6A4&PID_4100`）。"本机 HID 设备"列表可一键选用。默认已包含 W909 的三种连接方式：有线 `VID_B6A4&PID_4100`、2.4G 接收器 `VID_B6A4&PID_4101`、蓝牙 `VID&0002B6A4` / `VID&02B6A4`。旧配置启动时会自动补齐。

## W909 硬件说明 {#hardware}

| 控件 | 出厂行为 | 注意 |
|---|---|---|
| 1–9、0、`.`、`+`、`-`、ENTER、SPACE | 小键盘键码 | 可拦截 |
| 摇杆 上/下/左/右 | 方向键 | 可拦截 |
| 摇杆按下 | Enter | 可拦截，有独立物理身份，可与 ENTER 键分别绑定 |
| 旋钮按下 | **切换固件模式**，不发送按键 | 切换后 1–6 键会从数字变为 `A`–`F`；MacroHub 按物理身份识别，不受影响。本身是一个"纯可编程键" |
| 旋钮左旋/右旋 | 系统音量 −/+（所有固件模式） | 无法拦截（由 Windows 直接处理）。绑定其他功能时由 [旋钮音量保护](#volume-guard) 自动恢复音量 |

**连接方式**：有线（PID 4100）与 2.4G 接收器（PID 4101）已验证，两者的数据通道完全一致，按键、旋钮、灯光、电量都可用。蓝牙模式尚未验证；若蓝牙下没有厂商通道，改用"按键码"模式。

## 配置 JSON {#config-json}

**配置 JSON** 页可直接编辑完整配置：

- **应用到编辑器**：校验通过后载入页面（仍需"保存并应用"）。
- **导出文件 / 导入文件**：备份与迁移。
- **恢复默认配置**：覆盖已保存配置，不可撤销。

配置文件默认位置：`%APPDATA%\MacroHub\hub.json`（启动参数 `--config` 可指定）。

## 应用客户端协议 {#app-protocol}

供 UE 插件等应用接入。当前协议版本 **v2**。

### 通道 {#channels}

| 通道 | 地址 | 分帧 | 说明 |
|---|---|---|---|
| **命名管道（推荐）** | `\\.\pipe\MacroHub` | 每行一条 UTF-8 JSON（`\n` 结尾） | 无端口冲突；仅当前 Windows 用户可连接；断开立即可知；只收发给该应用的消息。UE 端可用 Core 自带的 `FPlatformNamedPipe` |
| WebSocket | `ws://127.0.0.1:17900/ws` | 每个文本帧一条 JSON | 与配置界面共用，会额外收到界面广播事件（可忽略） |

两个通道的消息完全相同。实测本机 WebSocket 往返中位 0.11 ms，传输本身不是瓶颈；应用端应在后台线程收消息、在游戏线程每帧开头统一处理。

### 握手 {#handshake}

```
应用                                  MacroHub
 │── 连接 ─────────────────────────► │
 │ ◄── {"type":"hello","role":"hub","protocol":2}
 │── {"type":"hello","role":"app","protocol":2,"app":"unreal-editor","pid":12345,"mode":"editor"} ►│
 │ ◄── {"type":"welcome","protocol":2,"clientId":"…","profile":{…},"controls":[…]}
```

`hello` 字段：

| 字段 | 必需 | 说明 |
|---|---|---|
| `role` | 是 | 固定 `"app"` |
| `protocol` | 建议 | 客户端支持的协议版本，缺省视为 1 |
| `app` | 是 | 应用标识，显示用 |
| `pid` | 建议 | 本进程 pid。**有 pid 时只按 pid 匹配前台**（同时开两个编辑器、或编辑器与 `-game` 独立进程都能区分） |
| `process` | 否 | 进程名；无 pid 时按进程名匹配 |
| `mode` | 否 | 运行模式，如 `editor` / `game`，显示与调试用 |

`welcome` 返回该进程匹配到的应用档案（`profile.forward` 决定会收到什么）以及全部控件列表（`id`、`label`、`kind`、`part`、`rect`），应用可据此生成自己的绑定界面。配置保存后 Hub 会推送同结构的 `profile` 消息。

### 事件（Hub → 应用） {#events}

只有当应用**在前台**时才会收到，内容由应用档案的“转发给应用客户端”决定：

**原始控件**（`forward = controls`，UE 插件推荐）：

```json
{ "type": "control", "seq": 1042, "t": 83412.613, "control": "KNOB_CW", "phase": "down", "kind": "knob", "part": "cw", "source": "pad" }
```

**功能事件**（`forward = functions`，或功能动作为“仅转发给应用”）：

```json
{ "type": "function", "seq": 7, "t": 83415.020, "function": "ue.play", "name": "PIE 运行", "control": "K1", "phase": "down", "layer": "unreal", "app": "unreal-editor" }
```

| 字段 | 说明 |
|---|---|
| `seq` | 每个连接独立递增的序号；出现跳号说明应用读取过慢、Hub 丢弃了积压的旧消息（每连接最多缓存 512 条） |
| `t` | Hub 单调时钟（毫秒，含小数），可用来计算旋钮转速做加速滑动 |
| `phase` | 每次操作都有 `down` 和 `up`；旋钮每转一格是一对 down/up |
| `source` | `pad`（实体按键）、`simulate`（界面/测试模拟） |

### 其他消息（应用 → Hub） {#app-messages}

| 消息 | 作用 |
|---|---|
| `{"type":"context","name":"Sequencer","detail":"LS_Intro"}` | 回报当前上下文，显示在配置界面（顶部“应用客户端”与测试台） |
| `{"type":"ping","t":123}` | 心跳，Hub 回复 `{"type":"pong","t":<hub>,"echo":123}` |
| `{"type":"simulate","control":"K1","phase":"down"}` | 模拟控件，调试用 |
| `{"type":"lighting","mode":1,"brightness":5,"speed":3,"direction":0,"color":"#ffffff"}` | 应用在线时设置键盘背光；`{"type":"lighting","reset":true}` 交还给 MacroHub |

### 回退与重连 {#fallback}

- 应用离线（未连接或已断开）时，Hub 对该应用按自己的层执行本地动作（模拟快捷键），保证插件没启动也能用。
- Hub 重启后连接会断开，应用应自动重连并重新发送 `hello`。
- 松开事件总是发给收到对应按下事件的那个应用，即使期间焦点已切走。

## 常见问题 {#faq}

**按宏键盘没反应？** 看顶部"宏键盘在线""键盘钩子"是否为绿；看"实时事件"是否出现 `signal`；出现 `→ 未知` 说明该控件签名不对，用 [学习按键](#learn)。

**快捷键在某个程序里无效？** 该程序若以管理员身份运行，需要用 `run.ps1 -Elevated` 启动 MacroHub。

**原来的数字还会打出来？** 确认当前层对该键不是"原样输出"；在测试台看"泄漏"计数，必要时调大等待时间。

**页面改了没生效？** 需要点"保存并应用"。

**旋钮用来切换标签页等功能时，屏幕上闪一下音量提示？** 这是旋钮硬件固定发送音量信号、MacroHub 立即恢复音量造成的，属正常现象，见 [旋钮音量保护](#volume-guard)。

**修改了功能的默认动作，别的层也变了？** 功能是共享的。只想改某一层时，新建一个功能再绑定。
